# Backend authorization regression suite

Run `dotnet build` and `dotnet test` from the repository root using `AIWorkHub.sln`. The solution includes all implemented backend projects and tests, including this suite. Docker must be running for the PostgreSQL integration tests. Databases are isolated disposable Testcontainers databases; application databases are not modified.

The HTTP tests run actual controllers, permission policies, JWT validation, tenant middleware, services and EF repositories against PostgreSQL. Test-only signed JWTs provide explicit actors/roles/permissions for endpoint isolation tests. Separate authentication tests obtain the local principal from the real company-login service with database-assigned roles, issue a JWT and use it on an HTTP endpoint. Google network/token verification remains the responsibility of the existing Google OIDC handler; test Google principals represent already validated provider tickets. The real ticket-received callback is exercised to verify rejection status, error code and suppression of session issuance.

Coverage includes developer A/B search and details, search counts/pagination, exact tenant scope in both directions, tenant-only administrators, project members and leads, project managers without membership, ID/key/project routes, restricted comments and all issue mutations, required authentication and permissions, update permission bypasses, trusted actor attribution on successful writes, audit isolation, tenant endpoints, missing provisioning, email verification, database-derived DEVELOPER/ADMIN JWTs, stale cookie claims and case-insensitive domain uniqueness.

`EndpointInventoryTests` tracks the 161 HTTP method/path combinations in the endpoint audit and checks registered routes and anonymous rejection where authorization is declared. Upload checks use multipart requests. These checks complement the authenticated workflow tests; a registered route or a 401 response alone does not prove its successful behavior. All three hubs reject anonymous negotiation. The board hub URL is `/hubs/boards/{boardId}`, not `/hubs/boards`.

`PasswordAuthHttpTests` exercises registration, verification, token replay rejection, incorrect and correct passwords, session cookies, current-user lookup, token issuance, logout, and revoked-session rejection over HTTP. Verification email is captured by a test sender. `CollaborationLiveTests` covers issue streaming and board WebSocket streaming, including cross-tenant board rejection. `NotificationsApiTests` exercises notification WebSockets.
